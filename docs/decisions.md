# DECISIONS.md — ADR проекта `factoria/`

Дата: 2026-11-05. Статус: действует для v1.
Связанные документы: `D:\agent-1c-demo\DECISIONS.md` (ADR-001…006 старого контура).

---

## ADR-101. Отдельный репозиторий `factoria/`, старый контур не трогаем
- **Решение:** новый код в `D:\factoria`, `D:\agent-1c-demo` продолжает работать как демо 1С+SCADA.
- **Причина:** big-bang ломает работающий контур; параллельная разработка даёт страховку (ТЗ §0 п.1, §12).
- **Статус:** принято.

## ADR-102. `ALLOW_EXTERNAL_API=false` по умолчанию
- **Решение:** значение по умолчанию — `false`. При `false` агент не вызывает внешний API и работает в read-only.
- **Причина:** совместимость с ADR-005 старого проекта (offline-only). Включение — осознанное действие с записью здесь.
- **Статус:** принято. Включение `true` фиксируется отдельным ADR.

## ADR-103. `AUTONOMY_MAX=A1` по умолчанию
- **Решение:** матрица §6.4 реализуется полностью (включая A2), но по умолчанию флаг `AUTONOMY_MAX=A1` — любое действие через подтверждение. `A2` включается переменной окружения.
- **Причина:** ТЗ §6.4 разрешает A2, но это смена политики «человек подтверждает любое действие». Для v1 и пилота безопаснее A1; A2 включается после статистики.
- **Статус:** принято. Расхождение с ТЗ осознанное: A2 не запрещён, а выключен флагом.

## ADR-104. `registry.yaml` — единственный источник правды по тегам
- **Решение:** все 21 тег, диапазоны, `max_age_seconds`, `speed_threshold`, method-ноды описаны в `backend/src/factoria/tags/registry.yaml`. `docs/tag-registry.md` и `frontend/src/scene/bindings.ts` **генерируются** из него.
- **Причина:** ТЗ §6.5, §5.4, §8.2 ссылаются на `registry.yaml`, но его схема не описана. Без единого источника три места разъедутся.
- **Статус:** принято. Схема — `docs/tag-registry.md`.

## ADR-105. Только method-ноды, writable-переменных нет
- **Решение:** `SetSpeed`, `SetRecipe`, `StartLine`, `StopLine`, `ReallocateJob` — методы OPC UA. Ни одна переменная не пишется напрямую.
- **Причина:** writable-переменная без callback не может отклонить запись; interlock должен жить в эмуляторе (ТЗ §4.3, §4.4).
- **Статус:** принято.

## ADR-106. 2D-панель работает с `/api/v1`, а не с `/api/*`
- **Решение:** Lovable-UI приводится к контракту нового backend (`/api/v1/...`). Слой совместимости со старым `/api/panel`, `/api/kpi`, `/api/top` не делаем.
- **Причина:** два контракта — двойная поддержка и место для ошибок. Старый UI остаётся на старом backend и не мешает.
- **Статус:** принято. Требует переписывания `src/lib/api.ts` после выгрузки UI.

## ADR-107. 1С в v1 — только чтение; мост остаётся запасным путём
- **Решение:** v1 использует `OnesAdapter` (`stub` → `http`). Запись (`update_production_plan`) исключена. Файловый мост `agent-1c-demo` не переносим, но оставляем рабочим в старом контуре как fallback для 4b.
- **Причина:** ТЗ §9.1, §1.3; ADR-002 старого проекта.
- **Статус:** принято.

## ADR-108. SQLite + Alembic с первого дня, PostgreSQL — на пилоте
- **Решение:** `sqlite+aiosqlite`, миграции Alembic в async-режиме (`alembic init -t async`). Переход на PostgreSQL — без изменения моделей.
- **Причина:** идемпотентность и аудит требуют транзакционной БД (ТЗ §5.5, §13); InfluxDB в v1 не нужна.
- **Статус:** принято.

## ADR-109. Целевая версия Python — 3.11+, фактическая машина — 3.14.3
- **Решение:** код пишем под 3.11+, но запускаем на единственном рабочем интерпретаторе 3.14.3. Версии зависимостей пинуются по факту проверки.
- **Причина:** `py -0p` показывает 3.11 (`D:\1\python.exe`) и 3.13, но обе установки нерабочие: файл 3.11 отсутствует, Store-алиас 3.13 не запускается. Подробности — `docs/assessment/technology-stack.md`.
- **Статус:** принято. Переустановка 3.11 — опция, не блокер: ядро стека на 3.14 уже работает.
- **Утверждено владельцем 2026-11-05:** остаёмся на 3.14.3, отдельно ставить 3.11 не будем.

## ADR-111. Локальный порт OPC UA — 48400, в docker — 4840
- **Решение:** по умолчанию эмулятор слушает `opc.tcp://0.0.0.0:48400`; в docker-compose — 4840.
- **Причина:** порт 4840 на машине разработки занят процессом `opcualds` (OPC UA Local Discovery Server, PID 5452), `bind` падает с `WinError 10013`. Порт вынесен в `OPCUA_ENDPOINT`.
- **Статус:** принято.

## ADR-112. Порог скачка уставки — по дельте, 800 об/мин
- **Решение:** `|new − current| > 800` → `BadInvalidState` (interlock). Второй порог `new > 400` остаётся политикой автономии (A1), а не отказом оборудования.
- **Причина:** ТЗ §6.2 даёт предикат «текущая SP < 400 и новая > 800», §6.5 — «|Δ| > 800». Это разные правила; принят §6.5 как более строгий и однозначный (OD-02).
- **Статус:** принято, закреплено тестом `test_delta_interlock_uses_absolute_delta`.

## ADR-113. Телеметрия backend — опрос, а не OPC UA subscription
- **Решение:** клиент читает все 21 тег раз в 0,5 c (`OpcuaClient.interval_s`), без `create_subscription`.
- **Причина:** data-change приходит только при изменении значения, поэтому у статичных тегов (`Running`, `Recipe.ID`) `SourceTimestamp` не обновляется и они ложно становятся `STALE`. Опрос даёт свежий ts и обнаруживает обрыв за 0,43 c (замерено).
- **Цена:** 42 чтения в секунду на 3 линии — приемлемо; при росте числа тегов вернуться к подписке с heartbeat.
- **Статус:** принято.

## ADR-110. FUXA и InfluxDB в v1 не используются
- **Решение:** витрина — HTML-страница backend; история — таблица `tag_history` в SQLite с ретенцией.
- **Причина:** Docker на машине отсутствует (CLI есть, демон не отвечает). ТЗ §0 п.6 разрешает план B.
- **Статус:** принято.
