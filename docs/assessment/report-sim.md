## 3. КАК СЧИТАЕТСЯ

- Физика — тот же `LineState`, что в эмуляторе: τ=2 c, нагрев, interlocks, автостоп.
- Случайность только через `random.Random(seed)`, поэтому один seed даёт один результат.
- `repro_hash` = sha256 от сценария, seed, горизонта, метрик и событий.
- Метрики: выпуск (у.е.), максимальная температура, средняя загрузка, время в работе, число аварий, время первой аварии, финальный рецепт.

## 4. ПРОВЕРКА (факт)

```
python -m pytest -q
164 passed
```

Ключевые тесты:

- `test_same_seed_same_result` — одинаковый seed → одинаковый хеш и метрики;
- `test_different_seed_differs` — другой seed → другой хеш (сценарий с возмущениями);
- `test_overload_stops_line` — автостоп по перегрузу, код 102;
- `test_hot_start_refuses_then_allows` — отказ 900 rpm при 85 °C, затем разрешение 300;
- `test_compare_route_not_shadowed_by_id` — маршрут сравнения не перехватывается `{id}`.

Скриншот: `checks/shots/experiments_1920.png` — два прогона, дельты выпуска, температуры, загрузки, времени в работе и аварий.

## 5. ЧЕСТНОСТЬ

- На экране написано: «данные симуляции — не факт с производства».
- Метрики — это физика нашей модели, а не измерение реального цеха.
- Прогон выполняется на сервере синхронно (десятки секунд максимум для 3600 c);
  очередь и отмена не делались.

## 6. ОГРАНИЧЕНИЯ

1. Один сценарий = одна линия; сравнение линий между собой не делалось.
2. Возмущения — только шум загрузки; отказы оборудования не моделируются.
3. История прогонов не чистится (ретенция не задана).
4. Сценарии заданы кодом, а не данными: новый сценарий — правка `scenarios.py`.
