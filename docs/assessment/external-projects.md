## 2. Что реально применимо к `factoria/`

### `IndustriAgents/OPCUA-MCP` (MIT, 31★) — самый полезный по паттернам

Читал README целиком. Ценность не в коде (это мост к OPC UA, а нам транспорт
к ПЛК запрещён §13), а в **инженерных решениях**:

| Паттерн | Как у них | Что у нас | Решение |
|---|---|---|---|
| Единый контракт инструментов в JSON, код генерируется из него | `contract/tools.json`, 15 инструментов, CI проверяет расхождение | 8 инструментов описаны прозой в §7.2, схемы пишутся руками | **взять**: `contract/commands.json` → Pydantic + TS |
| Профили доступа `observe` / `operator` / `full` | по умолчанию только чтение; запись — с allowlist | `AUTONOMY_MAX=A1`, A2 за флагом | **взять**: allowlist целей записи |
| Результат всегда с типом, статусом, временем и единицей | «never a bare number» | `{v,q,ts}`, единицы только в UI | **взять**: единицы в ответе API |
| Ошибка конфигурации останавливает старт | «misconfiguration stops the server at startup» | проверка `JWT_SECRET` уже есть | **взять**: запрет удалённого OPC UA без разрешения |
| Аудит каждого управляющего вызова | append-only файл | `audit_events` | уже есть |

### `selmux/ot-security-agent-skills` (Apache-2.0, 14★)

Набор навыков по форензике Modbus/BACnet/S7comm/IEC-104 и реагированию.
Кода нам не нужно, но **чек-лист** переносим: у нас нет ни одного документа
по безопасности OT, хотя мы подключаемся к OPC UA без шифрования.
Сделано: `docs/security/ot-baseline.md`.

### `midea-ai/SemaPLC` (MIT, 110★)

Генерация и верификация программ ПЛК из естественного языка. **Не берём**:
это генерация исполняемой логики управления — зона, где ошибка стоит дороже
всего, и в ТЗ её нет. Полезная идея — «сначала симуляция, потом загрузка» —
у нас уже реализована этапами: `sim` → `EXPERIMENTAL` → пилот.

### `dgiot` (Apache-2.0, 4862★) и `json-scada` (GPL-3.0, 499★)

Платформы промышленного IoT/SCADA с собственными драйверами и historian.
Нам не нужны: источник телеметрии — OPC UA-эмулятор, 1С — через адаптер.
Заменять их нашими 21 тегом бессмысленно, а тянуть 300 протоколов — против
принципа минимального стека. **Не берём.**

## 3. Лицензионная граница

| Лицензия | Проекты | Что можно |
|---|---|---|
| MIT / Apache-2.0 | OPCUA-MCP, selmux skills, SemaPLC, dgiot | читать, заимствовать идеи, при желании вендорить с сохранением уведомления |
| **GPL-3.0** | `WhiskeyHouse/ignition-mcp`, `riclolsen/json-scada`, wincc-mcp | **только читать**. Копирование кода в `factoria/` сделает проект производным и потребует раскрытия исходников |

Правило для репозитория: код GPL-проектов не копируется, даже фрагментами.
Идеи и схемы — можно, они не охраняются как код.

## 4. Бэклог заимствований

| ID | Что | Откуда идея | Этап | Оценка |
|---|---|---|---|---|
| EXT-1 | `contract/commands.json`: типы команд, параметры, границы, риск, обязательный `evidence`; из него генерируются Pydantic-модели и TS-типы | OPCUA-MCP | 4a | 1 день |
| EXT-2 | Allowlist целей записи (`allowed_write_targets`): даже при A2 команда вне списка отклоняется | OPCUA-MCP | 4a | 0,5 дня |
| EXT-3 | Единицы измерения в ответах API (`unit` рядом со значением) | OPCUA-MCP | 3 | 0,5 дня |
| EXT-4 | Чек-лист безопасности OT + запрет старта с удалённым OPC UA без явного флага | selmux skills | 2 | сделано |
| EXT-5 | Экспорт журнала аудита в формат, пригодный для SIEM (NDJSON + подпись цепочкой хешей) | OPCUA-MCP + OT-практика | 6 | 2 дня |

Отклонено: MCP-сервер как транспорт для наших агентов (у нас LangGraph in-process,
MCP добавит поверхность атаки без пользы для v1), генерация ПЛК-кода (SemaPLC),
замена OPC UA на dgiot/json-scada.

## 5. Вывод

Обзор был наполовину выдуман, но три проекта дали конкретные улучшения.
Самое ценное — не код, а **дисциплина контракта**: один JSON описывает
инструменты, из него генерируются схемы, и CI ловит расхождение. Это прямо
укрепляет наш этап 4a, где сейчас планировались ручные Pydantic-модели.

## 6. Стек общего назначения (проверка 2026-11-06)

Предлагался набор из 10 инструментов. Проверены версии, лицензии, число
зависимостей и модель развёртывания (PyPI / npm / GitHub API).

| Инструмент | Версия | Лицензия | Deps | Модель | Вердикт |
|---|---|---|---|---|---|
| LangGraph | 1.2.20 (у нас 1.2.19) | MIT | 6 | локально | **оставить** |
| Mem0 | 2.2.1 | Apache-2.0 | 56 | локально + vector store | **отложить** (этап 7) |
| Composio | 0.31.0 | не указана | 11 | SaaS, OAuth к чужим сервисам | **отклонить** |
| E2B | 2.63.0 | MIT (SDK) | 12 | облачные песочницы | **отклонить** |
| Browser Use | 0.13.14 | не указана | 62 | локально + браузер | **отклонить** |
| Docling | 2.148.0 | MIT | 11 + модели | локально | **отложить** (этап 6) |
| Open Interpreter | 0.4.3 | Apache-2.0 | 50 | локально, исполняет код | **отклонить** |
| LiveKit Agents | 1.8.11 | Apache-2.0 | 116 | облако/self-host | **отложить** (v2) |
| n8n | 2.46.6 | Sustainable Use (не OSI) | — | отдельный сервис + БД | **отклонить** |
| OpenHands | 92,7k★ | MIT | — | дев-инструмент | **не интегрировать** |

Почему отклонено: Composio выводит вызовы инструментов из нашего валидатора,
E2B и Open Interpreter дают модели исполнение кода, Browser Use — браузер с
чужими сессиями. Каждое из этого обходит §13 («LLM не имеет транспорта к ПЛК»)
и обесценивает главное отличие проекта. Mem0 и LiveKit — цена в зависимостях
(56 и 116) без задачи в v1. n8n дублирует наш оркестратор.

Политика закреплена ADR-117: runtime — только локальное, dev — отдельно,
облачные сервисы — только через отдельный ADR и решение владельца.
