- **Сущности**: 1 предприятие + 3 линии + 21 сигнал + 5 заказов + 3 спецификации = **33**.
- **Связи**: 3 `contains` + 21 `has_signal` + 5 `requires_spec` = **29**.

- **Версия** = `twin-<sha256(реестр)[:8]>`, стабильна при неизменном реестре.
- **Точность** = `null` всегда, пока нет валидированного набора данных.

## 5. ЧЕСТНОСТЬ ДАННЫХ

Сознательно не показывается:

- **точность** — нет исторического валидированного набора, число было бы выдумкой;
- **связь «заказ → линия»** — в stub-1С нет поля «линия», поэтому в предупреждениях
  прямо сказано, что связь появится с HTTP-сервисами (этап 4b);
- **история изменений двойника** — версии не сохраняются в БД, экран показывает
  текущий срез. Для истории нужна таблица `twin_versions` (не делалась).

## 6. ОГРАНИЧЕНИЯ

1. Двойник не обучается и не предсказывает: это представление структуры и
   качества данных. Название «двойник» здесь честно ограничено.
2. Нет персистентности версий: сравнить два среза во времени нельзя.
3. Покрытие зависит от кэша: при обрыве OPC UA оно падает до 0, и это правильно.

## 7. СЛЕДУЮЩИЙ ШАГ

- Таблица `twin_versions` + экран сравнения версий (полдня).
- Экран «Агенты»: без ключа DeepSeek — только каркас с явной пометкой «демо»,
  либо ждать ключ (этап 5 блокирован).
- HTTP-сервисы 1С (этап 4b) — блокированы доступом к базе.


## 8. История срезов (ADR-119)

Добавлено после решения о демо-режиме 1С.

| Что | Где |
|---|---|
| Таблица `twin_versions` | `storage/models.py`, миграция `5d4cbfde2d3a` |
| Сохранение и дельты | `model/history.py` |
| `GET /api/v1/twin/history`, `POST /api/v1/twin/snapshot` | `api/twin.py` |
| Панель «История срезов» | `frontend/src/pages/Twin.tsx` |

Срез фиксирует версию, покрытие, число сигналов в норме, свежесть, seq и
предупреждения. Дельта считается к предыдущему срезу; первый срез показывает
прочерк, а не ноль — иначе «ноль» читался бы как «изменений не было».

Проверка: 145 тестов, скриншот `checks/shots/twin_1920.png` — два среза,
Δ покрытия 0,00 и 0 сигналов, прочерк у первого.

Ограничение: срез снимается по кнопке (роль operator); расписание — следующий шаг.
