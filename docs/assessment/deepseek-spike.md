# DEEPSEEK-SPIKE.md — спайк §3.4

**Статус: НЕ ВЫПОЛНЕН.** Причина: нет `DEEPSEEK_API_KEY`, нет подтверждённого
разрешения на сетевой вызов. Пустой отчёт здесь — не «всё хорошо», а
«не проверено». Заполнять только фактическим выводом команд.

Спайк блокирует **только этап 5** (агенты). Этапы 1–4 от него не зависят.

## Чек-лист (6 проверок §3.4)

| # | Проверка | Команда | Ожидание | Fallback при провале |
|---|---|---|---|---|
| 1 | Алиас `deepseek-flash` существует | `curl -s -H "Authorization: Bearer $KEY" https://api.deepseek.com/beta/models` | в списке есть `deepseek-flash` | взять актуальный ID; если пусто — `LLM_PROVIDER=local` |
| 2 | Strict mode работает | один инструмент со `"strict": true`, `additionalProperties: false` | модель не добавляет лишних полей | клиентская валидация Pydantic перед вызовом |
| 3 | `tool_choice: required` + thinking | оба параметра в одном запросе | HTTP 400 | всегда отключать thinking при tool-calling |
| 4 | Thinking отключается | `{"thinking": {"type": "disabled"}}` | 200, без reasoning-блока | `reasoning_effort: "low"` |
| 5 | Контекст 1M / output 384K | вход ~100K токенов | 200 без обрезания | уменьшить `SessionBudget.token_limit` |
| 6 | Цена off-peak | 3–5 вызовов, сверка с прайсом | расчёт совпадает | зафиксировать фактическую цену в отчёте |

## Критерий готовности спайка

Все 6 пунктов заполнены **фактическим** выводом (код ответа, тело, число
токенов). Если хотя бы один пункт не проверен — спайк не пройден, этап 5
не начинается.

## Что нужно от владельца

1. Ключ `DEEPSEEK_API_KEY` (можно бюджетно ограниченный).
2. Явное разрешение на исходящий HTTPS к `api.deepseek.com`.
3. Лимит расхода на спайк (оценка: 5–10 вызовов, ~50–100 тыс. токенов).

## Что уже известно из ТЗ (допущения, не факты)

- `/beta` обязателен для strict; на обычном эндпоинте strict игнорируется.
- `tool_choice: required` вместе с thinking даёт 400.
- `minLength`/`maxLength`/`minItems`/`maxItems` не поддерживаются и молча игнорируются.
- Алиас `deepseek-flash` может отличаться от фактического ID.

Эти четыре пункта — из документа, а не из ответа API. До спайка они остаются
допущениями, на которых нельзя строить схемы инструментов.
