# REPORT — HTTPS, OPC UA TLS и визуальная проверка в CI

Дата: 2026-11-07. Исполнитель: opencode (DeepSeek V4.1 Flash).

## 1. HTTPS для API — работает

| Файл | Что |
|---|---|
| `scripts/gen_certs.py` | самоподписанный сертификат: SAN `localhost` + `127.0.0.1`, 365 дней, PEM |
| `scripts/run_backend_https.ps1` | запуск uvicorn с `--ssl-certfile/--ssl-keyfile` на `:8443` |
| `.gitignore` | `certs/` не коммитится |

Проверка (факт):

```
python scripts/gen_certs.py            → ключ и сертификат созданы
uvicorn --port 8443 --ssl-...          → запущен
curl -k https://127.0.0.1:8443/api/v1/health → 200
curl    http://127.0.0.1:8443/api/v1/health → 000 (TLS обязателен)
```

То есть API можно поднять по HTTPS без внешнего CA, а открытый HTTP на том же
порту не отвечает.

## 2. OPC UA TLS — не включён, и это не скрыто

Спайк на `asyncua 2.1.0` + Python 3.14.3: сервер с `Basic256Sha256`,
клиент с `set_security(...)` и закреплённым сертификатом сервера. Результат —
зависание на `SecureOpen` и таймаут. Проверены варианты:

- `Basic256Sha256_SignAndEncrypt` и `Basic256Sha256_Sign`;
- порядок `init → endpoint → load_certificate → set_security_policy` и с
  `set_security_IDs`;
- адрес `127.0.0.1` и `localhost` (SAN содержит оба);
- сертификаты в DER (PEM-ключи asyncua читает как DER — известное расхождение);
- разрешающий `set_certificate_validator` на сервере.

Ни один вариант не дал соединения. Поэтому:

- код эмулятора и клиента **не изменён** под TLS: непроверенный путь в
  основном контуре опаснее, чем его отсутствие;
- в `docs/security/ot-baseline.md` пункт 3.1 переведён в «частично»;
- для пилота нужен отдельный разбор (другая версия asyncua, Python 3.11/3.12
  или сертификаты через trust store), это не блокирует демо.

## 3. Визуальная проверка в CI

Добавлен job `visual` в `.github/workflows/ci.yml`:

1. поднимает эмулятор, backend на 8010 и Vite на 5173;
2. ждёт `/api/v1/health` и страницу;
3. запускает `scripts/shots.py` (все экраны, 4 ширины);
4. падает, если найден горизонтальный переполнение (`overflow: true`);
5. выгружает скриншоты артефактом на 14 дней, при падении — логи сервисов.

`shots.py` теперь:

- запускает встроенный Chromium, а при его отсутствии — системный Chrome
  (локально Chromium не скачивался);
- не валит job, если 3D-сцена не дала canvas (WebGL в headless бывает недоступен);
- возвращает код 1 при переполнении.

Проверка локально: `SHOTS_ONLY=login` → `exit=0`, скриншоты создаются.

## 4. ЧЕСТНЫЕ ОГРАНИЧЕНИЯ

1. **Визуальной регрессии в смысле «сравнение с эталоном» нет.** Job проверяет
   переполнение и складывает скриншоты; пиксельное сравнение с baseline не
   делалось (шрифты Linux и Windows дают ложные различия).
2. **OPC UA TLS не работает** — см. §2.
3. HTTPS проверен самоподписанным сертификатом; для пилота нужен нормальный
   CA или внутренний PKI.
4. Job `visual` ещё не запускался на GitHub: репозиторий локальный.
