# Решения интеграции спеки Stitch/Three.js в `D:\factoria`

Дата начала: 2026-11-08. Основание: `spec.md` (FACTORIA v4.8) из `three.js.html`.

## Цель
Интегрировать ценное из спеки в существующий `D:\factoria` (демо/витрина), не создавая второй продукт и не нарушая правила проекта.

## Принятые решения
1. **Источник правды данных** — существующий реестр тегов `backend/src/factoria/tags/registry.yaml` (L1-L3, OPC UA namespace `urn:mfg:emulator`). Спека оперирует другими станками (DMU 50/TRUMPF/FANUC/AGV, ns=2 `PLANT.*`); их *модель/описание* берётся как шаблоны отображения, но не заменяет OPC UA-реестр.
2. **1C — только read-only / экспорт.** Кнопка «прямой PUSH в 1C:ERP OData» из спеки не реализуется. Экспорт `EnterpriseData v1.14` / `NodeSet2` формируется из реальных данных/registry и отдаётся на скачивание/как пакет. Это соответствует правилу «1C stays read-only».
3. **Действия — A1 (человек подтверждает).** 1-click актуаторы спеки (`overclock_feed`, `reroute_agv`, `create_work_order`) в основном продукте не исполняют команду в транспорт; они создают запрос/рекомендацию на согласование (существующий контур approvals/commands), без транспорта к PLC (LLM/агент не пишет в оборудование).
4. **Без CDN в основном контуре.** React/Tailwind/Three.js/Babel из CDN — только в изолированном `prototype.html`. Основной фронт (`frontend/`, Vite) использует локальные зависимости.
5. **Без внешних API по умолчанию.** `ALLOW_EXTERNAL_API=false`; LLM-провайдерный слой — только если явно доступен (env), иначе детерминированный режим с маркировкой в UI.
6. **3D** — развиваем существующий процедурный `scene/Lathe.tsx` (привязка к `Speed.PV`), не заменяем на примитивную коробку из спеки.
7. **Standalone из спеки** хранится в `docs/spec/stitch-threejs/` как эталон для сверки, не деплоится.

## Расхождения тегов/моделей (спека vs проект)

| Спека (`templates_data.json` / kernel mock) | Проект (`registry.yaml`) | Решение |
|---|---|---|
| Станки ST-01..05: TRUMPF, Conveyor, DMU 50, FANUC, AGV | Линии L1,L2,L3 × теги `Running, Speed.SP/PV, Temp.PV, Load.Pct, Alarm.Code, Recipe.ID` | Шаблоны цеха = слой представления/сценарий над линиями L1-L3; маппинг явный и тестируемый. |
| Метрики: rpm/feed/vibration/spindleLoad/coolantBar/takt/queue | Физика: Speed/Temp/Load/Alarm/Recipe, history, sim | Очередь/такт/узкое место вычисляются из доступных сигналов+sim; недостающие поля — расчётные/помечены. |
| OPC nodes `ns=2;s=PLANT.*` | `urn:mfg:emulator`, `ns` проекта | Экспорт NodeSet2 генерирует из реального registry. |
| Действия: direct POST к актуаторам | Commands/approvals API, валидация, A1 | Рекомендация → approval/command request. |
