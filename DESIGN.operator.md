# DESIGN.operator.md — пульт оператора

Переопределяет §2–§3 `DESIGN.md` для маршрутов `/approvals`, `/production`,
`/commands/*`. Сетка, компоненты и запреты (§4–§9) действуют без изменений.

Почему отдельный файл: пульт читают в цеху, при плохом свете, на расстоянии
вытянутой руки, иногда в перчатках. Здесь важнее контраст и размер, чем плотность.

## 1. Отличия от базовой темы

| Параметр | База | Пульт | Причина |
|---|---|---|---|
| Контраст текста | 4.5:1 | **7:1** | чтение при бликах и пыли |
| Основной размер текста | 13 px | **15 px** | расстояние до монитора |
| Высота строки таблицы | 36 px | **44 px** | попадание пальцем/курсором |
| Главная кнопка | 32 px | **48 px** | нажатие без прицеливания |
| Минимальная зона нажатия | 28 px | **44 px** | перчатки |
| Пульсация | запрещена | **только `AWAITING_APPROVAL` и авария** | привлечь внимание |

## 2. Цвета (переопределение)

| Роль | Токен | Значение | Примечание |
|---|---|---|---|
| Фон | `bg/base` | `#070C12` | темнее базы, чтобы контраст был выше |
| Поверхность | `bg/surface` | `#101820` | |
| Граница | `border/default` | `#2A3A4C` | видна на солнце |
| Текст основной | `text/primary` | `#F2F6FA` | |
| Ожидает подтверждения | `status/warning` | `#FFC24B` | единственный «требует человека» |
| Авария | `status/danger` | `#FF5A52` | |
| Норма | `status/success` | `#37D07E` | |
| Подтверждено человеком | `status/approved` | `#7BD88F` | отдельный оттенок: «решено, не «работает» |

Правило: **красный и зелёный не различают дальтоники** — у каждого бейджа есть
иконка и текст (`✓ ИСПОЛНЕНО`, `✕ ОТКАЗ`, `⏳ ЖДЁТ`), цвет только дублирует смысл.

## 3. Компоненты пульта

### ApprovalCard
- Заголовок: что именно меняется, крупно (16 px, 600): «Уставка L2: 540 → 600 rpm».
- Таблица «было / станет»: две колонки, значения 20 px моноширинно.
- Риск: уровень `A1/A2`, причина отказа/подтверждения, уверенность агента в %
  (если есть) — но **не как единственный аргумент**.
- Таймер TTL: обратный отсчёт до `EXPIRED`, 20 px, `status/warning` при <60 c.
- Кнопки: «Согласовать» (48 px, primary, справа) и «Отклонить» (48 px, danger,
  слева от неё). Между ними — 16 px, чтобы промах не привёл к необратимому.
- Обязательные поля перед подтверждением: комментарий (≥10 символов) и чекбокс
  «Я проверил состояние линии». Без них кнопка `disabled`.

### OperatorHeader
Одна строка: линия, режим (`A1`/`A2`), качество данных, время последнего
обновления, кнопка `STOP LINE` (только для роли с правом, всегда secondary,
никогда не рядом с «Согласовать»).

### AlarmStrip
Появляется сверху при `Alarm.Code ≠ 0`: высота 32 px, фон `status/danger`,
текст капсом 12 px, код аварии и линия. Не закрывается кликом — только
исчезает, когда авария снята.

## 4. Клавиатура

| Клавиша | Действие |
|---|---|
| `A` | фокус на «Согласовать» (только в открытой карточке) |
| `R` | фокус на «Отклонить» |
| `Esc` | закрыть карточку без решения |
| `Space` | пауза автообновления списка |

Подтверждение по `Enter` **запрещено** — решение принимается осознанным кликом.

## 5. Что нельзя на пульте

- Автоподтверждение по таймауту и «согласовать всё».
- Скрывать TTL, чтобы карточка выглядела «спокойнее».
- Показывать `STALE`-данные как основание для решения без пометки.
- Размещать «Отклонить» и «Согласовать» вплотную.
- Анимация перехода между карточками дольше 120 мс.
