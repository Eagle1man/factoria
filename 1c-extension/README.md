# Расширение 1С `mfg` — публикация HTTP-сервиса

Шаблон написан агентом, **публикует человек**. Агент не меняет конфигурацию
и не публикует базу (ADR-107, ТЗ §9).

## 1. Что уже есть на машине

| Компонент | Факт |
|---|---|
| Платформа | 8.3.27.1508 (`C:\Program Files (x86)\1cv8t\8.3.27.1508`) |
| Конфигуратор | `1cv8t.exe` (толстый клиент + конфигуратор) |
| Публикация | `webinstt.exe` |
| База | файловая `C:\1c_bases\DemoAgent` |
| IIS | служба `W3SVC` работает, публикаций 1С пока нет |

## 2. Порядок действий

1. Открыть базу `DemoAgent` в конфигураторе.
2. **Расширение**: Конфигурация → Расширения конфигурации → добавить `mfg`
   (режим «Не снимать с поддержки»).
3. В расширении создать **общий модуль** `mfg_http` и вставить
   `mfg_http.bsl` из этого каталога.
4. В расширении создать **HTTP-сервис** `mfg`:
   - корневой URL: `mfg`;
   - шаблон `/orders/open` → метод GET → `СписокОткрытыхЗаказов`;
   - шаблон `/orders/{order_id}` → метод GET → `ПолучитьЗаказ`;
   - шаблон `/plan` → метод POST → `ЗаписатьПлан`.
5. Заменить блоки `TODO` в BSL под реальные метаданные конфигурации.
6. Опубликовать:

```
"C:\Program Files (x86)\1cv8t\8.3.27.1508\bin\webinstt.exe" ^
  -deploy -wsdir mfg -dir C:\inetpub\wwwroot\mfg ^
  -connstr "File=C:\1c_bases\DemoAgent;" ^
  -confpath C:\inetpub\wwwroot\mfg\default.vrd
```

7. Создать пользователя 1С с правами **только чтение** и выдать его логин.
8. Прописать в `.env`:

```
ONES_MODE=http
ONES_HTTP_URL=http://localhost/mfg/hs
ONES_HTTP_USER=<пользователь>
ONES_HTTP_PASSWORD=<пароль>
```

## 3. Проверка

```
curl -u <user>:<pass> http://localhost/mfg/hs/mfg/orders/open
```

Ожидается JSON `{"orders":[...]}`, а не HTML.

Backend: `GET /api/v1/orders` должен вернуть `"source": "http"`.

## 4. Чего здесь нет

- записи в 1С: `POST /hs/mfg/plan` отвечает 501 до отдельного ADR;
- конкретных имён документов: конфигурация неизвестна (OD-09), шаблон
  использует «Заказ клиента» как пример и требует правки;
- автоматической публикации: это действие человека.
