# AGENTS.md — frontend (рабочие правила)

Действуют для всего, что лежит в `frontend/`. Дополняют корневые правила проекта.

## 1. Дизайн-система обязательна

- Любой компонент пишется по `DESIGN.md` в корне репозитория.
- Цвета, отступы, радиусы, размеры шрифта **не изобретаются** в компоненте:
  берутся токены из frontmatter `DESIGN.md`.
- Маршруты пульта (`/approvals`, `/production`, `/commands/*`) — по
  `DESIGN.operator.md`; `/agents`, `/agents/:id/trace` — по `DESIGN.chat.md`.
- Вариант темы переопределяет только `colors` и `typography`. Сетка, компоненты,
  состояния и запреты общие.

## 2. Skill GradientDeck (`operate`)

В репозитории установлен skill `.agents/skills/gradientdeck` (версия 0.2.0).

- Режим — **`operate`**: успех — задача решена быстро и без сомнений, а не
  «выразительная страница».
- Перед первой правкой UI прочитать `craft.md` (пол качества).
- Для таблиц, панелей, фильтров, дашбордов — `apps-and-data.md`.
- Перед сборкой компонента проверить, есть ли он в `DESIGN.md` §Components;
  если да — использовать его правила, а не придумывать новые.
- После сборки — `review.md`, затем `polish.md`. Отчёт строкой `Review:`
  (что нашёл и исправил), без оценок и без «signature» в коде.
- Skill не перезаписывает `DESIGN.md`. `extract` запускается только когда UI
  уже существует и надо сверить документ с фактом.

## 3. Внешние стили

- `DESIGN.vendor.*.md` — не норма, а источник значений. Брать из них только
  поверхности, границы, радиусы и типографику.
- Запрещённое `DESIGN.md` (градиенты, декор, фото, засечные шрифты) не берётся,
  даже если есть в vendor-файле.
- В репозитории не больше двух vendor-файлов одновременно.

## 4. Данные

- Источник — только `/api/v1` и `WS /ws` (см. `docs/api.md`).
- Типы ответов — в `src/types`; ручные `any` запрещены.
- Мок-данные допустимы только при явной пометке «демо» в интерфейсе.
- `STALE` и `BAD` отображаются по `DESIGN.md` §Components: последнее известное
  значение как текущее не показывать.

## 5. Чего не делать

- Не подключать Supabase, внешнюю авторизацию, аналитику, шрифты с CDN
  (шрифты — локально, иначе пульт ломается без сети).
- Не добавлять UI-библиотеки, дублирующие дизайн-систему.
- Не реализовывать запись в 1С/ПЛК из браузера: только `POST /commands` и approve.
- Не добавлять декоративные иллюстрации и фотографии.

## 6. Проверки перед сдачей

```bash
npm run build      # без ошибок TypeScript
npm run lint       # без ошибок
python -m pytest tests/test_design_md.py -q   # дизайн-система не развалилась
```

Плюс визуальная проверка 1920 / 1280 / 1024 без горизонтального скролла
и наличия `banner-readonly` на каждом экране.
